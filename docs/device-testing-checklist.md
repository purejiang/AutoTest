# 真机验证清单（v1 验收）

> 本地无真机时全部自动化测试走 FakeDriver；以下项目**必须**在真机上逐项确认。
> 建议设备：≥1 台主力真机（Android 11+）+ 1 台受限 ROM（MIUI/EMUI 等，验证权限/后台限制）。
> 每项记录：设备型号 / Android 版本 / 结果 / 备注（用 `docs/` 下自建表格或写在本文件末尾）。

## 0. 环境前置

- [ ] `adb devices` 显示 `device` 而非 `unauthorized` / `offline`
- [ ] 开发者选项：USB 调试、USB 安装、**关闭"监控 ADB 安装应用"**类权限校验（MIUI 等）
- [ ] 屏幕锁定已关闭或设备已解锁（否则注入会落在锁屏）
- [ ] 首次运行 `sh scripts/setup.sh` 后 `uv run python ../scripts/check_env.py` 全 OK/WARN 合理
- [ ] 设置页可修改 adb 路径并生效（换机器模拟路径错误 → 报 DEVICE_UNAVAILABLE 而非 500）

## 1. 设备与手动控制（`/devices`）

- [ ] 设备列表显示型号/分辨率/Android 版本/占用状态，插拔后刷新正确
- [ ] 点击（绝对坐标）落点准确；长按触发应用内长按菜单
- [ ] 上/下/左/右滑动生效；拖拽（≥300ms）能拖动列表项/滑块
- [ ] 输入英文、数字、中文（中文注意 IME 限制，记录是否成功）；`clear_first` 能清空输入框
- [ ] 系统键：返回 / 桌面 / 最近任务 / 音量± / 电源（电源键行为在锁屏场景确认）
- [ ] 应用操作：启动（含指定 activity）、停止、清数据、重启；包名错误时报错清晰
- [ ] shell：`echo hi`、`pm list packages | wc -l`、长命令超时行为
- [ ] 截图：PNG 可打开、方向正确
- [ ] 录屏：开始/停止后 mp4 可播放（≥3s，无花屏）
- [ ] logcat 抽屉：近 200 行时间序正确
- [ ] 应用列表：第三方应用过滤正确

## 2. 镜像（scrcpy + WebCodecs）

- [ ] 启动镜像 ≤3s 出画面；`hello` 分辨率/旋转与实际一致
- [ ] 帧率接近设置值（30fps 设置下观感流畅，设置页 stats 丢帧少）
- [ ] **点击准确性**：在镜像 4 个角与中心各点一次，与真机落点一致（验证归一化→设备像素逆映射）
- [ ] **旋转**：设备旋转 90°/180° 后画面与点击仍准确（验证 SPS 变化重配 + 逆映射）
- [ ] `max_size=800` 时画面缩放正确且点击仍准确；`crop=w:h:x:y` 生效（若使用）
- [ ] 切到后台 10s 再回来：能自动恢复（requestKeyframe/重连）
- [ ] 拔线：UI 显示错误可重试，不白屏；重插后可重新启动镜像
- [ ] 不支持 WebCodecs 的浏览器（如旧 Firefox）：显示引导页，**不出现截图轮询**
- [ ] 镜像 + 录制同时进行时操作不卡顿（点击前 dump 的 ~300ms 延迟可感知但不影响正确性）

## 3. 脚本执行（`/scripts` + `/runs`）

- [ ] 导入 `samples/login_order.json`（替换包名/文案）后校验通过并跑通
- [ ] 12 类节点各至少一次成功执行：click / long_click / swipe / drag / input / key / wait(until) / app / shell / assert / screenshot / sub_script
- [ ] `when.mode=require` 目标不存在 → 节点 failed 且走 on_fail；`optional` 不存在 → skipped 不算失败
- [ ] `retry` 生效（制造首点失败后第二次成功）；成功后计数清零
- [ ] `on_fail=abort` 中止；`continue` 继续后续节点；`goto` 跳转且**重入后 retry 计数清零**
- [ ] `assert` 失败不重试动作（事件无 step_retry，直接 failed）
- [ ] `sub_script` 嵌套执行；脚本不存在 → 运行时错误清晰；嵌套 >5 层报错
- [ ] 节点 `timeout_ms` 超时 → failed 且 error 可读
- [ ] 三环保护：`engine.max_steps` 调小 + goto 死循环 → 被截断并标失败
- [ ] `screenshot_on_fail` 失败时产物里有截图；`screenshot` 节点产物正常
- [ ] 变量插值 `{{account}}` 生效；未知变量有日志告警
- [ ] 步骤耗时/尝试次数在运行详情正确显示
- [ ] 运行结束后状态正确（succeeded/failed/aborted/stopped）

## 4. 暂停 / 干预 / 恢复（v5 语义）

- [ ] 运行中点暂停：≤5s 内停下；页面出现"已暂停"并可**手动控制设备**
- [ ] 暂停期间的手动操作产生 `manual_intervention` 事件（事件流可见）
- [ ] 恢复前 resume-check 显示：设备在线、前台包名、耗时、破坏性节点提示
- [ ] 热恢复继续执行（从暂停的节点继续）
- [ ] 当前节点 `rerun_safety=destructive`（如 app clear/install/shell 破坏性）时，"重跑当前节点"入口被禁用
- [ ] 停止：立即停止，正在执行的动作最多等 5s，最终状态 stopped
- [ ] 调试：设断点 → 命中断点暂停；单步执行下一节点；"从节点重跑"
- [ ] 运行中断线/杀后端重启 → 该运行标 `interrupted`（不假装成功），提示从节点重跑

## 5. 录制

### 5.1 网页镜像录制（主）
- [ ] 开始录制 → 在镜像上点 3 个不同按钮 → 停止 → 事件数与操作数一致
- [ ] 点击归因：能匹配到按钮文本/资源 id（高置信度），空白区域回退坐标（medium/low 有角标）
- [ ] 滑动被识别为 swipe；长按（≥500ms）识别为 long_click；拖拽（≥300ms 移动）识别为 drag
- [ ] 输入文本产生 input 节点，文本完整
- [ ] 暂停录制期间的操作**不**入账；继续后恢复入账
- [ ] 转脚本：生成的脚本校验通过，且回放能复现操作
- [ ] 录制事件可单条删除后再转脚本
- [ ] 录制中尝试启动运行 → 409 冲突提示正确（反之亦然）

### 5.2 物理录制（辅助）
- [ ] 能识别触摸设备（`getevent -pl`）；识别失败有清晰错误而非静默
- [ ] 2 点标定后点击位置与识别坐标一致（在 3 个不同位置点按验证）
- [ ] 旋转后坐标仍正确（旋转时间线）
- [ ] 物理按键（返回/音量）被记录为 key 节点
- [ ] 时钟锚点正确（事件时间序与设备一致）

## 8. 已知限制（不是 bug，验收时确认文案有说明）

- 密码框输入无法回读校验（u2 限制），只标"未校验"
- 物理录制在受限 ROM 上可能无 `getevent` 权限 → 走网页录制
- 不支持 WebCodecs 的浏览器不做镜像，走物理录制
- 冷恢复（重启后继续原运行）**v1 不提供**：会标 `interrupted` 并引导从节点重跑
- 元素吸附/图像匹配/OCR 为 v1.1 计划
